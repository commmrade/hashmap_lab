Постановка задачи
"Реализовать функционал работы с хеш-таблицей (вид хеш-таблицы, метод разрешения коллизий, первичная и вторичная хеш-функции - см. свой вариант задания) (предметная область и ключ соответствуют заданию 1).
Подпрограммы: инициализация (с возможностью задания начального размера), освобождение памяти, первичная хеш-функция, вторичная хеш-функция, функция добавления (с проверкой уникальности ключа), функция удаления (при полном совпадении всех полей записи, а не только ключа), функция поиска, печать."
Входные данные
"1) Текстовый файл (input.txt), содержащий 1 000 000 строк. Каждая строка имеет 3 поля в табличном виде:
 Поле 1: Дата (Структура: день, месяц, год — целые числа).
 Поле 2: ФИО (строка).
 Поле 3: Номер заявки (целое число).
 Все данные во входном файле корректные (проверять на корректность не нужно).
 2) Целое число n — количество строк для обработки (10 ≤ n ≤ 1 000 000).
 3) Составной ключ поиска (см. свой вариант задания из ЛР1)."
 Выходные данные
 "1) Текстовый файл (output_hash.txt), строки которого содержат данные хеш-таблицы.
 2) Номер строки входного файла, в которой найден заданный ключ поиска.
 3) Количество шагов поиска."
 Порядок выполнения
 "1) Загрузить n строк из входного файла в хеш-таблицу. При загрузке вызывать функцию добавления с проверкой ключа на уникальность (повторные ключи не добавляются, фиксируется факт дубликата). 
 2) Вызвать подпрограммы работы с хеш-таблицей:
 - поиск по заданному ключу (в том числе — ключ, которого нет);
 - поиск при коллизии;
 - удаление существующей записи (по полному совпадению всех полей);
 - удаление несуществующей записи;
 - удаление при коллизии;
 - печать таблицы.
 3) Сохранить итоговую хеш-таблицу в выходной файл."
 Содержание отчета
 "1. Титульный лист.
 2. Неформальная постановка задачи.
 3. Описание класса: поля, методы — заголовок, назначение, список формальных параметров, входные данные, выходные данные.
 4. Текст программы.
 5. Тесты ПО БЕЛОМУ ЯЩИКУ:
 - добавление: проверка уникальности ключа; добавление при коллизии;
 - поиск: ключ не существует; ключ существует; поиск при коллизии;
 - удаление: ключ существует; ключ не существует; удаление при коллизии; проверка не только ключа, но и значения, ассоциированного с ключом (т.е. удаление должно учитывать полное совпадение всех полей записи).
 6. Сравнение с результатами задания 1: сравнить количество шагов поиска в хеш-таблице с количеством шагов поиска в исходном (неотсортированном) файле и в отсортированных файлах из задания 1, сделать вывод об эффективности хеш-поиска."
 7. Ограничения реализации
 8. "Предусмотреть возможность первоначального задания размера хеш-таблицы.
 Функционал для разрешения коллизий при добавлении / удалении / поиске вынести в отдельную подпрограмму (не дублировать логику)."
